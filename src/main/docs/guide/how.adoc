Pyronaut connects Python code to the https://docs.micronaut.io/latest/guide/[Micronaut framework] through decorators.
This section explains how the decorators map to Micronaut annotations, what the `pyronaut` command does with your source
before it runs, and which runtime features the Pyronaut SDK includes for you.

== Use Micronaut annotations as decorators

Micronaut uses annotations such as `@Controller`, `@Get`, `@Singleton`, and `@Value`. Pyronaut exposes these annotations
as Python decorators. Import them from the Java package with the leading `io.` removed:

[source,python]
----
from micronaut.http.annotation import Get


@Get(value="/", produces="text/plain")
def index() -> str:
    return "Hello from Pyronaut"
----

Pyronaut omits the `io.` prefix because `io` is a Python standard-library module and a package cannot shadow it. When the
https://docs.micronaut.io/latest/api/[Micronaut API reference] lists `io.micronaut.http.annotation.Get`, import it as
`micronaut.http.annotation.Get`. Packages that do not start with `io.micronaut` keep their original names, such as
`jakarta.inject.Singleton` and `jakarta.validation.constraints.NotBlank`.

Pass annotation members as keyword arguments, for example `@Get(value="/", produces="text/plain")`, or pass a single
positional argument for the `value` member, as in `@Get("/")`. A decorator on a Python class corresponds to a type-level
annotation. A decorator on a function or method corresponds to a method-level annotation.

Use `typing.Annotated` for annotations that Java applies to fields or parameters. It keeps the type hint and annotation
together:

[source,python]
----
from typing import Annotated

from jakarta.validation.constraints import NotBlank, Size
from micronaut.http.annotation import Body


def save(name: Annotated[str, NotBlank, Size(min=1, max=30)], payload: Annotated[Item, Body]) -> Item:
    ...
----

A bare name inside `Annotated`, such as `NotBlank`, applies the annotation with its default values. Call the annotation
to pass members.

=== Python names for DI and validation

Import `singleton`, `not_blank`, and `valid` from `pyronaut.annotations` to use Python spellings of
`jakarta.inject.Singleton`, `jakarta.validation.constraints.NotBlank`, and `jakarta.validation.Valid`:

[source,python]
----
from typing import Annotated
from pyronaut.annotations import singleton, not_blank


@singleton
class GreetingService:
    def greet(self, name: Annotated[str, not_blank(message="Name required")]) -> str:
        return f"Hello {name}"
----

Use `Annotated[Item, valid]` for cascading validation of an introspected request body or bean argument.
These names produce the same Micronaut metadata during `pyronaut process`; DI and validation run through
Micronaut-managed beans. They do not validate ordinary Python calls or dataclass constructors, and do not
replace `@dataclass`, `@Introspected`, or `@Serdeable`.

=== Names that clash with Python keywords

Some Java members and methods use names that Python reserves as keywords. Append an underscore to the Python name, and
Pyronaut maps it back to the Java name:

[source,python]
----
from micronaut.http.annotation import Error


@Error(global_=True)          # Java member: global
def handle(request, error):
    ...
----

The same rule applies to packages and methods. For example, use `micronaut.core.async_.annotation` for
`io.micronaut.core.async.annotation` and `Flux.from_(publisher)` for `Flux.from`.

== Using Java classes directly

Import any Java class on the classpath with a normal `import` statement. This works for classes from Micronaut, the JDK,
and libraries declared in `pyproject.toml`:

[source,python]
----
from java.time import Duration
from org.apache.commons.lang3 import StringUtils

print(StringUtils.capitalize("hello"))
timeout = Duration.ofSeconds(5)
----

`java.type("org.apache.commons.lang3.StringUtils")` is an equivalent way to obtain the same class. The Micronaut
examples use it for reactive types such as `Mono` and `Publisher`. It is also useful when a Java package name would
shadow a Python module.

Use Java objects from Python by calling Java-named methods such as `response.getHeaders()`, indexing Java lists and maps,
and iterating over Java collections. Python `str`, `int`, `float`, `bool`, `list`, `dict`, `datetime`, and `uuid.UUID`
values convert to matching Java types when passed to Java code. See
<<usingPackagesJavaLibraries,Using Python Packages and Java Libraries>> to declare dependencies.

== What happens during processing

When you run `pyronaut dev`, `pyronaut run`, or `pyronaut test`, the CLI first runs `pyronaut process`. Processing reads
your Python sources and passes decorators, type hints, dataclasses, and abstract classes to the Micronaut compiler. The
compiler generates Java classes and metadata for:

* Bean definitions describing how to construct each `@Singleton`, `@Controller` or `@Factory` and which dependencies to inject.
* Route metadata for every HTTP method decorator, including how to bind each parameter.
* Serializers and deserializers for `@Serdeable` dataclasses.
* Validation metadata for `jakarta.validation` constraints.
* Bridge code that lets Java call your Python functions and lets Python receive Java objects.
* An OpenAPI description of the routes.

Pyronaut writes processed output to `__pyronaut__/classes`. When no processing input has changed, it reuses the complete
output. By default, a changed input triggers a clean compilation; optional incremental processing can retain unaffected
output and process a smaller source set. Processing can report source and generated-metadata errors before the server
starts. The processor must be able to see decorators statically; see <<incrementalProcessing,Incremental processing>>
for the constructs it can and cannot follow.

To see how processing handles serialization and validation, define a data class:

.Writing serializable data classes
[source,python]
----
from dataclasses import dataclass
from typing import Annotated

from com.fasterxml.jackson.annotation import JsonProperty
from jakarta.validation.constraints import NotBlank, Pattern, Size
from micronaut.serde.annotation import Serdeable


@Serdeable                                                   # <1>
@dataclass
class Person:
    name: Annotated[str, NotBlank, Size(min=1, max=30)]      # <2>
    age: Annotated[int, JsonProperty("person_age")]          # <3>
    telephone: Annotated[str | None, Pattern(regexp=r"\d{10}")] = None
----

<1> `@Serdeable` asks Micronaut Serialization to generate a JSON encoder and decoder for the class.
<2> Micronaut checks the `jakarta.validation` constraints whenever it validates a `Person`, for example as a request body annotated with `Valid`.
<3> `JsonProperty` renames the attribute in JSON to `person_age`.

Processing produces a serializer that writes `{"name": ..., "person_age": ...}`, a validator that enforces the
constraints, and a Python-to-Java bridge that lets a controller return a `Person` directly. The application does not
need runtime reflection or startup schema generation for this behavior.

== Included runtime support

You do not need to declare the core Micronaut runtime in `pyproject.toml`. The launchers used by `pyronaut dev` and
`pyronaut run` include:

* the Netty HTTP server and client
* Micronaut Serialization and Micronaut Validation
* the TOML configuration loader
* management endpoints
* retry and scheduling
* WebSocket support
* OpenAPI annotations
* the Python `asyncio` bridge
* Logback logging

Add other Micronaut modules, such as Micronaut Data or Micronaut Security, and third-party Java libraries under
`[tool.pyronaut.dependencies]`.
