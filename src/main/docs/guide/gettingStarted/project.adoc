Use this guide to create a Pyronaut project, add an HTTP route, configure the
application, and run a test. If you prefer direct-source mode, follow the
<<fastApiTutorial,FastAPI tutorial>> instead.

[[prerequisites]]
== Step 1: Complete the prerequisites

Pyronaut runs Python application code and Python tests on GraalPy, not on CPython.
`pyronaut setup` provisions the GraalPy version used by Pyronaut, and `pyronaut --version` shows it:

[source,bash]
----
pyronaut setup
pyronaut --version
----

If https://github.com/pyenv/pyenv#installation[pyenv] is installed, setup installs GraalPy with pyenv; otherwise it
downloads GraalPy into `~/.pyronaut/sdks`.

== Step 2: Create the project

From the directory where you want the project created, run:

[source,bash]
----
pyronaut create hello-pyronaut
cd hello-pyronaut
----

Add `--features data-jdbc,mysql` to the `pyronaut create` command when you need those Micronaut features.
The generated project includes `src/main.py` for logging setup, `tests/test_application.py` as a starter test, and
`config/application.toml` for application settings. The following steps add an HTTP route, configure its port, and
replace the starter test.

The following optional subsection briefly explains the project configuration. Skip it to continue with the generated
files.

=== Review the project configuration (optional)

`pyproject.toml` is the standard Python project file. The generated file contains Python project metadata and Pyronaut
settings, including Java dependencies by scope. Keep it as generated for this tutorial. To change project settings, see
<<pyproject,Configuring pyproject.toml>> and <<dependencies,Installing Python and Java Dependencies>>.

[[project-installation]]
== Step 3: Install project dependencies

Run `pyronaut install` after creating the project and whenever you change its dependencies:

[source,bash]
----
pyronaut install
----

This command creates a GraalPy virtual environment in `.venv` and installs the Python dependencies declared in
`pyproject.toml` or `requirements.txt`, plus `pytest` when the project has Python tests. Pyronaut uses this environment
for application and test launches. It also resolves the Java dependencies declared in `pyproject.toml`. A CPython-created
environment cannot provide packages to the embedded GraalPy runtime.

See <<usingPackagesJavaLibraries,Using Python Packages and Java Libraries>> for Python package compatibility and Java
library guidance.

== Step 4: Add an HTTP route

An HTTP route maps an HTTP method and path to a Python function. This example declares a module-level route function; it
does not define a controller class annotated with `@Controller`.

`src/main.py` configures logging. Leave it in place and create `src/hello_pyronaut/controllers.py` with:

[source,python]
----
from micronaut.http.annotation import Get


@Get(value="/", produces="text/plain")
def index() -> str:
    return "Hello from Pyronaut"
----

The `@Get` decorator maps `GET /` to the `index` function. Group routes in a `@Controller` class when they share a
prefix or need injected services. See <<httpApis,Building HTTP APIs>> for more options.

== Step 5: Add application configuration

Add the server port to the generated `config/application.toml`:

[source,toml]
----
[micronaut.application]
name = "hello-pyronaut"

[micronaut.server]
port = 8080
----

The `config/` directory is on the runtime classpath. Use `application.toml` for Micronaut settings such as the server
port, data sources, and application-specific properties. See <<configurationInjection,Configuration Injection>> to read
those settings from Python.

== Step 6: Run the application

Start the development server:

[source,bash]
----
pyronaut dev
----

`pyronaut dev` prepares and starts the application in one command. It:

* installs the Java dependencies declared in `pyproject.toml`;
* processes the Python sources; and
* enables file watching so that edits reload the application.

After changing dependencies, rerun `pyronaut install`. To inspect processing errors without starting the server, run
`pyronaut process`.

Verify the route:

[source,bash]
----
curl http://localhost:8080/
----

The response is `Hello from Pyronaut`.

== Step 7: Add and run a test

Replace the generated `tests/test_application.py` file with:

[source,python]
----
import pytest
import requests

from pyronaut.test import MicronautTest, micronaut_test_fixture


@pytest.fixture
def my_context(request):
    fixture = micronaut_test_fixture(request, MicronautTest())  # <1>
    yield fixture
    fixture.stop()


@pytest.fixture
def client(my_context):
    return requests.with_context(my_context)  # <2>


def test_index(client):
    response = client.get("/")
    assert response.status_code == 200
    assert response.text == "Hello from Pyronaut"
----

<1> `micronaut_test_fixture` starts the application and an embedded HTTP server on a random port for the fixture's
duration.
<2> `requests.with_context` returns a `requests`-compatible client whose relative URLs point at the embedded server,
so the test does not need to know the port. The `micronaut-pyronaut-requests` test dependency provides it.

Run the test suite through Pyronaut so that the Micronaut classpath, processed sources, and GraalPy runtime are set up
consistently:

[source,bash]
----
pyronaut test
----

Pyronaut runs pytest inside the application's JVM and writes an HTML report to
`__pyronaut__/reports/tests/index.html`. See <<testing,Testing>> for JUnit-style Python tests, test selection, and Test
Resources.
