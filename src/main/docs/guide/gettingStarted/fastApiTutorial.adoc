= The FastAPI Tutorial

This tutorial recreates the https://fastapi.tiangolo.com/#example[FastAPI example] using Pyronaut.

It is for readers familiar with FastAPI who want to learn Pyronaut.

You will use standard Python type hints, generate OpenAPI documentation, validate input, reload the application during
development, and run an automated test.
First <<installation,install Pyronaut>> and run `pyronaut setup`. This direct-source workflow uses the embedded GraalPy
runtime and JUnit 5 integration, so it does not require a project virtual environment or `pytest`.

== Start the development server

Run the development server from the directory containing `main.py`:

[source,bash]
----
pyronaut dev
----

When you omit the source argument, `pyronaut dev` detects `main.py` in the current directory. Development mode watches
the source and reloads the application after changes.
The server listens on `http://localhost:8080` by default.

== Verify the routes

Verify the root route:

[source,bash]
----
curl http://localhost:8080/
----

The response is:

[source,json]
----
{"Hello":"World"}
----

Verify the item route:

[source,bash]
----
curl "http://localhost:8080/items/5?q=somequery"
----

The response is:

[source,json]
----
{"item_id":5,"q":"somequery"}
----

The application now:

* handles `GET` requests at `/` and `/items/{item_id}`.
* converts `item_id` to an `int`.
* accepts the optional `q` query parameter as a `str`.
* returns both responses as JSON.

Verify validation with a path value that Pyronaut cannot convert to an integer:

[source,bash]
----
curl -i http://localhost:8080/items/foo
----

A representative response begins:

[source,text]
----
HTTP/1.1 400 Bad Request
----

== Explore the API documentation

* Open http://localhost:8080/swagger-ui/index.html[Swagger UI] to explore and call the API interactively.
* Open http://localhost:8080/redoc/index.html[ReDoc] for an alternative view of the same API documentation.

Pyronaut generates the OpenAPI description from the routes and Python types while processing `main.py`.

`Item` is a standard Python dataclass. `@Serdeable` enables generated JSON serialization, while `Valid`, `NotBlank`, and
`Positive` apply Micronaut Validation to the request body.
The HTTP operations remain module-level functions. `Valid` enables validation for the request body, so an explicit
`@Validated` declaration is not needed. This example does not require reflection or a Pydantic model.

The development server reloads the application automatically. Verify the new `PUT` operation:

[source,bash]
----
curl -X PUT http://localhost:8080/items/5 \
  -H 'Content-Type: application/json' \
  -d '{"name":"Foo","price":42.0,"is_offer":true}'
----

The response is:

[source,json]
----
{"item_name":"Foo","item_id":5}
----

The Swagger UI and ReDoc pages now include the request body and its validation constraints. Verify validation with an
invalid body:

[source,bash]
----
curl -i -X PUT http://localhost:8080/items/5 \
  -H 'Content-Type: application/json' \
  -d '{"name":"","price":-1}'
----

The response begins:

[source,text]
----
HTTP/1.1 400 Bad Request
----

== Test the application

Create `test_main.py` next to `main.py`:

[source,python]
----
include::src/main/docs/examples/gettingStarted/fastapi/upgraded/test_main.py[]
----

Run the application and test sources together:

[source,bash]
----
pyronaut test main.py -- test_main.py
----

`MicronautTest()` starts and stops an embedded server for the generated JUnit 5 test module.
`requests.with_context` accepts the injected `ApplicationContext` and provides a `requests`-compatible client backed by
the Micronaut HTTP client. The test covers the root response, path and query binding, a valid request body, and a
validation failure.
Functions whose names start with `test` become JUnit 5 test methods automatically. You do not need a top-level test
class, an `@Test` decorator, a `self` parameter, or a return annotation. Injected values are available through
module-level attributes. The development server does not need to run separately.

== Run the application

Run the same source file with `pyronaut run`:

[source,bash]
----
pyronaut run main.py
----

Pyronaut processes and runs the source directly. This direct-source workflow does not require a separate application
server.

== Summary

With standard Python type hints and Pyronaut decorators, the application provides:

* Request definitions that use standard Python type hints and dataclasses.
* Conversion and validation of path, query, and JSON body values.
* Generated JSON serialization without runtime reflection.
* Automatic OpenAPI generation with Swagger UI and ReDoc.
* Development-time reloads with `pyronaut dev`.
* Standalone HTTP integration tests with `MicronautTest()` and `pyronaut test`.

Declare the types once and reuse them for HTTP binding, validation, serialization, documentation, and tests.
