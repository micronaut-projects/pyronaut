Python applications usually read configuration from `os.environ`, a `.env` file or a `pydantic-settings` model. Pyronaut uses Micronaut's configuration model: it reads configuration from many sources with a defined priority, converts it to the types your code declares, can validate it at startup and injects it into beans.

== Where configuration comes from

Pyronaut merges configuration from several sources. Later entries in this list override earlier ones:

. `config/application.toml` (or `.yml`, `.properties`, `.json`) on the classpath.
. Environment-specific files such as `config/application-dev.toml` and `config/application-test.toml`. Which ones apply depends on the active environments (see below).
. Environment variables, using upper-case with underscores: `MICRONAUT_SERVER_PORT=9090` sets `micronaut.server.port`.
. Java system properties passed with `-D`, and `--property key=value` arguments for direct-source runs.

Every property has a dotted name such as `micronaut.server.port`. In TOML the dots become tables:

[source,toml]
----
[micronaut.application]
name = "bookstore"

[micronaut.server]
port = 8080

[bookstore.catalog]
url = "https://catalog.example.com"
timeout = "5s"
page-size = 50
----

The configuration binder normalises key styles, so `page-size`, `pageSize` and `PAGE_SIZE` all refer to the same property. Prefer kebab-case in files and upper snake case in environment variables.

TIP: After `pyronaut install`, `config/application.toml` carries a JSON schema directive. Editors that understand TOML schemas (VS Code with the Even Better TOML extension, PyCharm) then autocomplete Micronaut property names and flag typos. `pyronaut validate-config` performs the same check from the command line; see <<validateConfig,Configuration validation>>.

== Environments

An environment is a named profile such as `dev`, `test` or `production`. Pyronaut activates environments from the `MICRONAUT_ENVIRONMENTS` environment variable or the `micronaut.environments` property, and detects some automatically (for example `test` during `pyronaut test`). For each active environment, Pyronaut loads `application-<env>.toml` on top of `application.toml`.

This replaces the common Python pattern of `if os.environ.get("ENV") == "production":`. Keep shared settings in `application.toml` and only the differences in the environment files.

== Injecting single values

`@context.Value` injects one property into an attribute or a constructor parameter. The `${name:default}` syntax provides a fallback:

[source,python]
----
from typing import Annotated

from pyronaut import context


@context.Singleton
class CatalogClient:
    url: Annotated[str, context.Value("${bookstore.catalog.url}")]
    page_size: Annotated[int, context.Value("${bookstore.catalog.page-size:20}")]
----

The configuration binder converts the raw string to the declared type, so `page_size` is an `int`. Durations such as `"5s"` convert to `java.time.Duration`, and comma-separated values convert to `list[str]`.

`@context.Property(name="...")` does the same without the placeholder syntax and is slightly clearer when no default is needed:

[source,python]
----
from pyronaut import context


@context.Singleton
class CatalogClient:
    url: Annotated[str, context.Property(name="bookstore.catalog.url")]
----

== Configuration classes

Injecting values one at a time does not scale. `@context.ConfigurationProperties` binds an entire prefix to a class, the way a `pydantic-settings` model binds environment variables. Each attribute maps to a property under the prefix, type hints drive conversion and the configuration binder enforces `jakarta.validation` constraints when it creates the bean:

[source,python]
----
from typing import Annotated

from pyronaut import context, validation


@context.ConfigurationProperties("bookstore.catalog")
class CatalogConfig:
    url: Annotated[str, validation.NotBlank]
    timeout: str = "5s"
    page_size: Annotated[int, validation.Min(1)] = 20
----

Configuration classes are beans, so any other bean can receive one through its constructor:

[source,python]
----
@context.Singleton
class CatalogClient:
    def __init__(self, config: CatalogConfig):
        self.config = config
----

Nested classes map to nested tables:

[source,python]
----
@context.ConfigurationProperties("bookstore")
class BookstoreConfig:
    @context.ConfigurationProperties("catalog")
    class Catalog:
        url: str | None = None

    name: str = "Bookstore"
    catalog: Catalog = Catalog()
----

[source,toml]
----
[bookstore]
name = "My Bookstore"

[bookstore.catalog]
url = "https://catalog.example.com"
----

=== Immutable configuration

A frozen dataclass produces an immutable configuration bean. The configuration binder passes the bound values to the generated constructor:

[source,python]
----
from dataclasses import dataclass
from typing import Annotated

from pyronaut import context, validation


@context.ConfigurationProperties("vat")
@dataclass(frozen=True)
class ValueAddedTaxConfiguration:
    percentage: Annotated[float, validation.NotNull]
----

=== Validating at startup

The application context checks constraints on a configuration class when it first creates the bean. Add `@context.Context` (`micronaut.context.annotation.Context`) to a configuration class to create it eagerly, so an invalid deployment fails immediately at startup rather than on the first request that touches it.

=== Repeated configuration

`@context.EachProperty` creates one bean per entry under a prefix. It is the Micronaut equivalent of a dictionary of settings, for example several named data sources:

[source,toml]
----
[datasources.primary]
url = "jdbc:postgresql://db1/app"

[datasources.reporting]
url = "jdbc:postgresql://db2/app"
----

[source,python]
----
from typing import Annotated

from pyronaut import context


@context.EachProperty("datasources")
class DataSourceConfig:
    url: str | None = None

    def __init__(self, name: Annotated[str, context.Parameter]):
        self.name = name   # "primary" or "reporting"
----

Injecting `list[DataSourceConfig]` returns every entry, and `Annotated[DataSourceConfig, context.Named("reporting")]` selects one.

== Conditional beans and configuration

`@context.Requires` from <<dependencyInjection,Dependency Injection>> reads configuration too. Use it to enable optional features:

[source,python]
----
@context.Singleton
@context.Requires(property="bookstore.cache.enabled", value="true")
class CachingCatalogClient(CatalogClient):
    ...
----

== Configuration in tests

`MicronautTest(properties={...})` overrides properties for a pytest fixture, and `MicronautTest(environments=[...])` chooses environments. Test-only files belong in `tests-config/`, which Pyronaut adds to the classpath during `pyronaut test` only. See <<micronautTest,Using MicronautTest>>.
