Pyronaut applications expose HTTP APIs with the same decorators Micronaut uses in Java, while the Python code looks familiar to FastAPI users: functions with type hints, path variables in braces, and dataclasses for request and response bodies. This section covers the common patterns and their Flask and FastAPI equivalents.

== Routes

A route is a function decorated with an HTTP method decorator from the `pyronaut.http` facade (see <<facades,Pyronaut Facades>>), which exposes the annotations of `micronaut.http.annotation`. The decorators are `@http.Get`, `@http.Post`, `@http.Put`, `@http.Patch`, `@http.Delete`, `@http.Head` and `@http.Options`. Routes can live at module level, which is the quickest way to start, or inside a `@http.Controller` class, which groups related routes under a common prefix and lets them share injected dependencies:

[source,python]
----
from pyronaut import http


@http.Controller("/books")
class BookController:
    def __init__(self, service: BookService):
        self.service = service

    @http.Get("/")
    def list_books(self) -> list[Book]:
        return self.service.list()

    @http.Get("/{isbn}")
    def get_book(self, isbn: str) -> Book | None:
        return self.service.find(isbn)
----

A module with routes but no `@http.Controller` receives an implicit controller mounted at `/`. Call `http.Controller("/prefix")` at module level to change the prefix without introducing a class.

Path variables use `{name}` in the route and a parameter of the same name in the function. The parameter's type hint drives conversion, so `item_id: int` rejects non-numeric values with `400 Bad Request`.

== Binding request data

Micronaut binds function parameters from the request using the parameter name, the type hint and an optional decorator inside `typing.Annotated`:

[cols="2,3", options="header"]
|===
|Parameter |Bound from

|`item_id: int` with `{item_id}` in the route
|The path variable.

|`q: str \| None = None`
|The query parameter `q`. Parameters that are not path variables bind from the query string; a default value makes them optional.

|`Annotated[str, http.QueryValue("page-size")]`
|A query parameter whose name differs from the Python name.

|`Annotated[str, http.Header("X-Request-Id")]`
|A request header. `Annotated[str, http.Header]` infers the header name from the parameter name.

|`Annotated[str, http.CookieValue("session")]`
|A cookie.

|`Annotated[Item, http.Body]`
|The request body, decoded from JSON into the dataclass. `Annotated[str, http.Body]` receives the raw text.

|`request: http.HttpRequest`
|The full request object, for headers, the URI or attributes.
|===

Each `Annotated` form has a shorter equivalent that calls the annotation as the default value, such as
`request_id: str = http.Header("X-Request-Id")`: see <<annotationDefaults,Applying Annotations to Parameters and Attributes>>.

Model a JSON body with a dataclass decorated with `@serde.Serdeable` (`micronaut.serde.annotation.Serdeable`). This replaces a Pydantic `BaseModel`: the decorator makes Micronaut generate the JSON encoder and decoder during processing, without reflection or runtime schema building:

[source,python]
----
from dataclasses import dataclass
from typing import Annotated

from pyronaut import http, serde, validation


@serde.Serdeable
@dataclass
class Item:
    name: Annotated[str, validation.NotBlank]
    price: Annotated[float, validation.Positive]
    is_offer: bool | None = None


@http.Post("/items")
def create_item(item: Annotated[Item, http.Body, validation.Valid]) -> Item:
    return item
----

`validation.Valid` asks Micronaut Validation to check the constraints declared on the dataclass before the function runs. You can also apply constraints directly to parameters, for example `page: Annotated[int, validation.Min(1)] = 1`.

TIP: Dataclasses may reference each other and contain lists, dictionaries, enums, `datetime`, `date`, `timedelta` and `uuid.UUID` fields. Quote forward references (`"Room | None"`) when the referenced class is declared later in the file. Rename a JSON property with `Annotated[int, serde.JsonProperty("person_age")]` (Jackson's `JsonProperty`, also in the `pyronaut.serde` facade).

== Responses

The return type hint decides how Micronaut encodes the response:

[cols="1,2", options="header"]
|===
|Return type |Response

|`dict`, `list`, a `@serde.Serdeable` dataclass, or a list of them
|JSON with `Content-Type: application/json`.

|`str`
|Text. Set `@http.Get(produces=http.TEXT_PLAIN)` or `@http.Produces(http.TEXT_PLAIN)` to send plain text rather than a JSON string.

|`None`
|`404 Not Found`. Returning `None` from a lookup is the idiomatic "not found" response.

|`http.HttpResponse`
|Full control of status, headers and body: `http.created(item)`, `http.notFound()`, `http.ok(body).header("X-Total", "3")`. These functions are the `HttpResponse` static methods, so `http.HttpResponse.created(item)` works too.

|`http.HttpStatus`
|An empty response with the given status.

|`Publisher`, `Mono`, `CompletionStage`, or an `async def` function
|Asynchronous responses; see <<threading,Threading, blocking work, and asyncio>>.
|===

Change the status of a successful response with `@http.Status`:

[source,python]
----
from pyronaut import http


@http.Post("/items")
@http.Status(http.status.CREATED)
def create_item(item: Annotated[Item, http.Body]) -> Item:
    return item
----

== Errors

Exceptions raised from a route become `500 Internal Server Error` responses with a JSON error body. Validation failures and binding failures become `400 Bad Request`. To customise error handling, declare an `@http.Error` method. Inside a controller it handles errors from that controller; with `global_=True` it handles errors from every route:

[source,python]
----
from micronaut.http.hateoas import JsonError
from pyronaut import http


class BookNotFound(Exception):
    pass


@http.Controller("/books")
class BookController:
    @http.Get("/{isbn}")
    def get_book(self, isbn: str) -> Book:
        raise BookNotFound(isbn)

    @http.Error
    def on_not_found(self, request: http.HttpRequest, e: BookNotFound) -> http.HttpResponse:
        return http.notFound().body(JsonError(f"No book {e}"))

    @http.Error(status=http.status.NOT_FOUND)
    def on_404(self, request: http.HttpRequest) -> http.HttpResponse:
        return http.notFound().body(JsonError("Nothing here"))
----

`JsonError` is not part of a facade, so it keeps its direct `micronaut.http.hateoas` import; both styles mix freely. The exception type of the second parameter selects which exceptions the handler receives, and `status=` selects a status code instead. For application-wide handling of one exception type, implement an `http.ExceptionHandler` bean as shown in the https://docs.micronaut.io/latest/guide/#exceptionHandler[Micronaut guide].

== Calling other services

The `requests` library works in Pyronaut through the `pyronaut-requests` shim (see <<pyronautRequests,Pyronaut Requests>>), but for services you call regularly a declarative client is more convenient. Declare an abstract class describing the remote API and Micronaut implements it:

[source,python]
----
from abc import ABC, abstractmethod

from pyronaut import http


@http.client.Client("https://api.example.com/catalog")
class CatalogClient(ABC):
    @http.Get("/books/{isbn}")
    @abstractmethod
    def find(self, isbn: str) -> Book:
        ...
----

Inject `CatalogClient` like any bean. Declaring the method `async def` returns an awaitable instead of blocking; see <<asyncAwait,Using async/await>>. `@http.client.Client("catalog")` with a `micronaut.http.services.catalog.url` property keeps the URL in configuration.

== OpenAPI documentation

Pyronaut generates an OpenAPI description from your routes and dataclasses during processing and serves Swagger UI at `/swagger-ui/index.html` and ReDoc at `/redoc/index.html` in development mode. Add descriptions with the annotations in `io.swagger.v3.oas.annotations`, which are available as decorators, for example through `from pyronaut import openapi` and `@openapi.Operation(summary="...")`.
