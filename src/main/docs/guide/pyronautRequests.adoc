Pyronaut Requests provides a subset of the Python https://requests.readthedocs.io[`requests`] API. The Micronaut HTTP client
performs the underlying work, and the client can also target an embedded server in tests.

Add it to the scope where you need it. For application code declare it under `runtime`; for tests only, under `test`:

[source,toml]
----
[tool.pyronaut.dependencies]
runtime = [
  "io.micronaut.pyronaut:micronaut-pyronaut-requests"
]
----

Direct-source files can declare it inline with `Dependency(group="io.micronaut.pyronaut", module="micronaut-pyronaut-requests")`.

== Quick start

[source,python]
----
import requests

response = requests.get("https://httpbin.org/get", params={"q": "pyronaut"})
print(response.status_code, response.json())
----

`import pyronaut.requests as requests` is equivalent to the `requests` shim and avoids shadowing a `requests` package installed in the virtual environment.

== Supported API

- Functions: `request`, `get`, `post`, `put`, `patch`, `delete`, `head`, `options`, and `Session` (usable as a context manager)
- Request options: `params`, `data`, `json`, `files`, `headers`, `cookies`, `auth` (basic auth tuple), `timeout`, `allow_redirects`, `verify`
- Response: `status_code`, `reason`, `ok`, `url`, `headers` (case-insensitive, iterable), `content`, `text`, `json()`, `raise_for_status()`
- Exceptions under `requests.exceptions`: `RequestException`, `ConnectionError`, `Timeout`, `HTTPError`

Not supported: a per-request `proxies` argument, streaming responses (`stream=True`), and SSL contexts beyond `verify=False`. For proxies, use standard proxy environment variables or set `Session.proxies`.

When a request uses `timeout`, `verify` or `allow_redirects` values that differ from the defaults, Pyronaut creates a
short-lived Micronaut client with those settings and closes it after the request.

== Typed JSON

`response.json()` returns Python `dict` and `list` values. Pass a class to deserialize with the Micronaut Serialization
integration, using the same `JsonMapper` configuration as the application:

[source,python]
----
from dataclasses import dataclass

from micronaut.serde.annotation import Serdeable


@Serdeable
@dataclass
class Message:
    message: str


response = client.get("/hello/John")
message = response.json(Message)
assert message.message.startswith("Hello")
----

== Use with MicronautTest

`requests.with_context(context)` binds a client to a running Micronaut application context. Relative URLs resolve against the `EmbeddedServer` in that context and JSON uses the context's `JsonMapper`:

[source,python]
----
import pytest
import requests

from pyronaut.test import MicronautTest, micronaut_test_fixture


@pytest.fixture
def my_context(request):
    fixture = micronaut_test_fixture(request, MicronautTest())
    yield fixture
    fixture.stop()


@pytest.fixture
def client(my_context):
    return requests.with_context(my_context)


def test_hello_world(client):
    response = client.get("/hello/John")
    assert response.status_code == 200
    assert response.json()["message"]
----

See <<requestsTesting,Using Requests for Testing>> for more test patterns.

== Client lifecycle

Pyronaut registers Micronaut HTTP clients in a registry. The shutdown listener closes them when an application context
stops, and an `atexit` hook closes any clients that remain at interpreter exit. Use `Session` as a context manager
(`with requests.Session() as session:`) to close a session's client deterministically.

NOTE: The shutdown listener closes every registered client when any application context stops. In a test suite that starts several contexts in one JVM, create clients with `with_context` per fixture rather than sharing module-level sessions across contexts.
