This section builds a small but complete Pyronaut project: a `pyproject.toml`, one HTTP route, application configuration and a test. If you would rather start from a single file, the <<fastApiTutorial,FastAPI Tutorial>> shows the no-project workflow.

Complete the <<prerequisites,Prerequisites>> first. They set up the GraalPy virtual environment that the testing step needs.

TIP: `pyronaut create demo` generates an equivalent project for you, optionally with extra Micronaut features such as `--features data-jdbc,mysql`. The steps below build the same project by hand so that every file is explained.

== Create `pyproject.toml`

`pyproject.toml` is the standard Python project file. Pyronaut reads its own settings from the `[tool.pyronaut]` tables and leaves the rest to the Python packaging tools:

[source,toml]
----
[project] # <1>
name = "hello-pyronaut"
version = "0.1.0"
dynamic = ["scripts"]

[build-system]
requires = ["setuptools", "wheel", "tomli"]
build-backend = "setuptools.build_meta"

[tool.pyronaut]
repositories = ["mavenCentral"] # <2>

[tool.pyronaut.dependencies] # <3>
runtime = []
build = []
test = [
  "io.micronaut.pyronaut:micronaut-pyronaut-pytest",
  "io.micronaut.pyronaut:micronaut-pyronaut-requests"
]
----

<1> Standard project metadata. The name and version are also used when packaging the application.
<2> Where Java libraries are downloaded from. Maven Central is the Java equivalent of PyPI.
<3> Java dependencies, grouped by scope. `runtime` libraries are available to the application, `build` libraries only during processing (annotation processors), and `test` libraries only to tests. Here the runtime is empty because the Pyronaut launcher already bundles the Micronaut HTTP server, serialization and validation; see <<how,How Pyronaut Works>>.

Dependencies use Maven `group:artifact` coordinates. Micronaut modules are versionless because Pyronaut resolves their versions from the Micronaut platform; third-party libraries need an explicit `group:artifact:version`.

== Add a controller

Create `src/controllers.py`:

[source,python]
----
from micronaut.http.annotation import Get


@Get(value="/", produces="text/plain")
def index() -> str:
    return "Hello from Pyronaut"
----

Module-level functions decorated with an HTTP method decorator become routes; this module is mounted at `/`. Group routes into a `@Controller` class when they share a prefix or need injected services, as described in <<httpApis,Building HTTP APIs>>.

== Add application configuration

Create `config/application.toml`:

[source,toml]
----
[micronaut.application]
name = "hello-pyronaut"

[micronaut.server]
port = 8080
----

Everything under `config/` is on the classpath at runtime. `application.toml` holds Micronaut configuration such as the server port, data sources and your own settings; <<configurationInjection,Configuration Injection>> explains how to read those settings from Python.

== Run the application

If you have just installed or upgraded Pyronaut, provision the SDK once:

[source,bash]
----
pyronaut setup
----

Then start the development server:

[source,bash]
----
pyronaut dev
----

`pyronaut dev` runs three steps for you: `pyronaut install` downloads the Java dependencies declared in `pyproject.toml` and generates editor stubs, `pyronaut process` compiles the Python sources into Micronaut metadata, and the application starts with file watching enabled so that edits trigger a reload. You can run the first two steps on their own when you change dependencies or want to see compile errors without starting the server:

[source,bash]
----
pyronaut install
pyronaut process
----

Call the application:

[source,bash]
----
curl http://localhost:8080/
----

== Add a test

Create `tests/test_controller.py`:

[source,python]
----
import pytest
import requests

from pyronaut.test import MicronautTest, micronaut_test_fixture


@pytest.fixture
def my_context(request):
    fixture = micronaut_test_fixture(request, MicronautTest())  # <1>
    yield fixture
    fixture.stop()


@pytest.fixture
def client(my_context):
    return requests.with_context(my_context)  # <2>


def test_index(client):
    response = client.get("/")
    assert response.status_code == 200
    assert response.text == "Hello from Pyronaut"
----

<1> `micronaut_test_fixture` starts the application, including an embedded HTTP server on a random port, for the duration of the fixture.
<2> `requests.with_context` returns a `requests`-compatible client whose relative URLs point at that embedded server, so the test does not need to know the port. The `micronaut-pyronaut-requests` test dependency provides it.

Run the tests through Pyronaut so that the Micronaut classpath, processed sources and the GraalPy runtime are set up consistently:

[source,bash]
----
pyronaut test
----

Pyronaut runs pytest inside the application's JVM and writes an HTML report to `__pyronaut__/reports/tests/index.html`. See <<testing,Testing>> for JUnit-style Python tests, test selection and Test Resources.
