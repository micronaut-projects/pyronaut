= Python Logging with Logback

Pyronaut provides a Python-friendly logging configuration API that uses Logback as the backend instead of Python's built-in logging system. This eliminates GIL/threading issues in GraalPy applications and provides unified logging across Java and Python components.

== Why Logback for Python?

In traditional Python applications, logging is handled by Python's built-in `logging` module. However, when running Python code on GraalPy within a Java application:

- Python's logging system can create GIL contention
- Log output is isolated from the main application's logging
- Configuration and management becomes fragmented

By using Logback as the backend for Python logging, you get:

- **Unified logging**: All logs (Java and Python) go through the same Logback infrastructure
- **Better performance**: No GIL issues with logging operations
- **Centralized configuration**: Configure all logging from one place
- **Rich ecosystem**: Access to Logback's extensive appender and filtering capabilities

== Basic Configuration

Use the familiar Python `dictConfig` format to configure logging. See the https://docs.python.org/3/library/logging.config.html#logging-config-dictschema[Python dictConfig documentation] for the complete schema reference.

[source,python]
----
from logback.config import dictConfig

LOGGING = {
    "version": 1,
    "disable_existing_loggers": False,

    "formatters": {
        "standard": {
            "format": "%(asctime)s [%(levelname)s] %(name)s: %(message)s"
        }
    },

    "handlers": {
        "console": {
            "class": "logging.StreamHandler",
            "level": "INFO",
            "formatter": "standard"
        },
        "file": {
            "class": "logging.handlers.RotatingFileHandler",
            "level": "INFO",
            "formatter": "standard",
            "filename": "app.log",
            "maxBytes": 10_000_000,
            "backupCount": 5,
            "encoding": "utf-8"
        }
    },

    "root": {
        "level": "INFO",
        "handlers": ["console", "file"]
    },

    "loggers": {
        "my.module": {
            "level": "DEBUG",
            "handlers": ["file"],
            "propagate": False
        }
    }
}

dictConfig(LOGGING)
----

== Handler Translation

Pyronaut automatically translates Python logging handlers to Logback appenders:

| Python Handler | Logback Appender | Notes |
|---------------|------------------|--------|
| `logging.StreamHandler` | `ConsoleAppender` | Outputs to System.out |
| `logging.FileHandler` | `FileAppender` | Basic file logging |
| `logging.handlers.RotatingFileHandler` | `RollingFileAppender` | Size-based rotation |

=== Handler Configuration

Most handler configuration options are translated directly. For example:

[source,python]
----
"handlers": {
    "file": {
        "class": "logging.handlers.RotatingFileHandler",
        "filename": "app.log",
        "maxBytes": 10_000_000,
        "backupCount": 5,
        "encoding": "utf-8"
    }
}
----

Becomes a Logback `RollingFileAppender` with:
- File: `app.log`
- SizeAndTimeBasedRollingPolicy with maxFileSize: 10MB
- FixedWindowRollingPolicy with maxIndex: 5

== Format Translation

Python format strings are automatically translated to Logback patterns:

| Python Format | Logback Pattern |
|---------------|-----------------|
| `%(asctime)s` | `%d{yyyy-MM-dd HH:mm:ss.SSS}` |
| `%(levelname)s` | `%level` |
| `%(name)s` | `%logger` |
| `%(message)s` | `%msg` |

Logback patterns automatically include newlines (`%n`) for proper log separation.

== Using Logback Appenders Directly

For advanced use cases, you can bypass the translation layer and use Logback appenders directly:

[source,python]
----
LOGGING = {
    "version": 1,
    "handlers": {
        "smtp": {
            "class": "ch.qos.logback.classic.net.SMTPAppender",
            "smtpHost": "smtp.example.com",
            "to": ["admin@example.com", "user@example.com"],
            "from": "noreply@example.com",
            "subject": "Application Error",
            "layout": {
                "class": "ch.qos.logback.classic.PatternLayout",
                "pattern": "%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"
            }
        }
    },
    "root": {
        "level": "ERROR",
        "handlers": ["smtp"]
    }
}
----

=== Property Configuration

When using Logback appenders directly:

- **Simple properties**: Use `"propertyName": "value"` for `setPropertyName(value)` calls
- **List properties**: Use `"propertyName": ["value1", "value2"]` for multiple `addPropertyName(value)` calls
- **Nested objects**: Some appenders support nested configuration objects

=== Supported Appenders

You can use any Logback appender by specifying its full class name. Common appenders include:

- `ch.qos.logback.core.ConsoleAppender` - Console output
- `ch.qos.logback.core.FileAppender` - File output
- `ch.qos.logback.classic.net.SMTPAppender` - Email notifications
- `ch.qos.logback.classic.net.SyslogAppender` - Syslog output
- `ch.qos.logback.core.rolling.RollingFileAppender` - Advanced file rotation

See the https://logback.qos.ch/manual/appenders.html[Logback documentation] for available appenders and their configuration options.

== Integration with Python Logging

Once configured, use Python logging normally:

[source,python]
----
import logging

logger = logging.getLogger(__name__)
logger.info("This log message goes through Logback")
----

The logs will appear in your configured Logback appenders with proper formatting and routing.
