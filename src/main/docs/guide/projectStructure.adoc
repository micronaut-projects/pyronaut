== Pyronaut Toolchain

Pyronaut requires an installed GraalVM toolchain. GraalVM can be installed in a variety of ways, refer to the https://www.graalvm.org/downloads/[GraalVM download page] for more information.

If you don't want to install GraalVM manually then Pyronaut will provision an installation using the configured toolchain settings and install it to `USER_HOME/.pyronaut/sdks`.

[source,toml]
----
[tool.pyronaut.toolchain]
type = "jvm" # jvm|native
distribution = "ee"
java-version = 25
version = "25i2"
----

It is important to note there are two possible toolchains (`native` and `jvm`) that have different trade offs.

The `jvm` toolchain requires a GraalVM a Java runtime and provides better peak performance at the cost of startup time and memory consumption.

The `native` toolchain provides better startup time, better memory consumption and is often preferred for development time when fast restarts and test execution are ideal. You can choose to use the native toolchain locally and still deploy a JVM application or vica versa.

The following table summarizes the trade-offs.

|===
|Characteristic |JVM |Native

|Startup Time
|Slower
|Faster

|Memory Consumption
|Greater
|Lower

|Compatibility
|Broad Java Library Compatibility
|Some Libraries Require Metadata

|Peak Performance
|Superior
|Requires PGO Optimization
|===

NOTE: Direct code execution (`pyronaut run App.py`) always selects the `native` toolchain by default.

== Pyronaut Project Layout

Pyronaut reads project layout from `[tool.pyronaut.sources]` in `pyproject.toml`.
All configured paths are relative to the project root.

The default layout is:

[source,text]
----
.
|-- pyproject.toml
|-- src/
|   `-- application Python sources
|-- src-java/
|   `-- optional Java application sources
|-- config/
|   `-- application.toml and other application resources
|-- tests/
|   `-- pytest sources
|-- test-java/
|   `-- optional Java test sources
|-- tests-config/
|   `-- test-only resources
`-- __pyronaut__/
    `-- generated Pyronaut state
----

The default source settings are:

[source,toml]
----
[tool.pyronaut.sources]
python = "src"
python-test = "tests"
java = "src-java"
java-test = "test-java"
resources = "config"
test-resources = "tests-config"
additional-resources = []
additional-test-resources = []
----

`pyronaut process` compiles the configured Python and Java source trees into `__pyronaut__/classes`.
For tests, Pyronaut also creates `__pyronaut__/test-classes` from the application and test source sets.

== Resource Directories

The `resources` directory is added to the runtime classpath for `run`, `test`, and build operations.
The `test-resources` directory is added only for tests.

Use `additional-resources` for application resource directories that should be available in run, test, JVM wheel, and Docker packaging flows.
Use `additional-test-resources` for test-only resource directories.

[source,toml]
----
[tool.pyronaut.sources]
resources = "config"
additional-resources = ["views", "assets"]
test-resources = "tests-config"
additional-test-resources = ["tests-fixtures"]
----

== Generated Files

The `__pyronaut__` directory contains generated state such as dependency manifests, processed classes, test reports, validation reports, schemas, and IDE stubs.
When incremental processing is enabled, compiler state is stored separately for the main and test passes under `__pyronaut__/incremental/main` and `__pyronaut__/incremental/test`.
When the compiler daemon is enabled, its authenticated local endpoint metadata and detached diagnostics are stored under `__pyronaut__/daemon`.
It is safe to delete this directory when you want a clean local Pyronaut state; the CLI recreates it as needed.
