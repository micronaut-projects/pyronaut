= Testing

Pyronaut supports JUnit 5 tests, pytest tests, or both through the JUnit Platform.
Use `pyronaut test` when tests need the Micronaut classpath, processed sources, test resources, or Micronaut test integration.

== Selecting a Test Engine

Configure the engine under `[tool.pyronaut.test]`:

[source,toml]
----
[tool.pyronaut.test]
engine = "both" # junit|pytest|both
----

The default is `both`, preserving the current behavior. `junit` runs only JUnit Jupiter tests, `pytest` runs only pytest tests, and `both` runs both engines in one JUnit Platform launch.

JUnit tests written as Python modules can use module-level `MicronautTest()` and JUnit lifecycle annotations such as `BeforeAll` and `BeforeEach`. Pytest tests use pytest fixtures, scopes, parametrization, marks, and plugins. A module-level JUnit `MicronautTest()` module is owned by JUnit and is excluded from pytest discovery when both engines are enabled.

Add the pytest integration to the test scope:

[source,toml]
----
[tool.pyronaut.dependencies]
test = [
  "io.micronaut.pyronaut:micronaut-pyronaut-pytest",
  "io.micronaut.test:micronaut-test-junit5"
]
----

Run all tests:

[source,bash]
----
pyronaut test
----

VS Code's Python pytest support invokes pytest directly and is not suitable for Micronaut-backed Pyronaut tests.
Use the Pyronaut VS Code Test Explorer extension when running these tests from VS Code.
See <<vscodeExtension,VS Code Test Explorer Extension>>.

`pyronaut test` performs install and process preflight, runs configuration validation for the `test` scenario, starts configured project test resources, and delegates discovery to the configured engines. For direct sources, Test Resources starts only when runtime dependencies and inline runtime `@AppConfig` declarations identify a missing property supported by an inferred provider. Use `--disable-test-resources` to disable either form of automatic orchestration.

== JUnit 5 Python Modules

The JUnit engine supports Python modules as JUnit 5 tests. Invoke `MicronautTest()` at module level. Top-level functions whose names start with `test` become test methods, while helper and lifecycle functions are also defined at module level. Injected values are available through their module-level attributes.

[source,python]
----
from typing import Annotated

from jakarta.inject import Inject
from micronaut.context import ApplicationContext
from micronaut.test.extensions.junit5.annotation import MicronautTest
from org.junit.jupiter.api import BeforeEach

MicronautTest()

context: Annotated[ApplicationContext, Inject]

@BeforeEach
def verify_context():
    assert context.isRunning()

def test_context():
    assert context.isRunning()
----

JUnit module tests can run in direct source mode. They do not use pytest fixtures or require a Python virtual environment.

== Direct JUnit 5 Tests

For a small application, Java or Python sources can be tested without a project manifest. By default, direct tests recursively discover `**Test.java` files for Java and `*Test.py` or `test_*.py` modules for Python from the current working directory:

[source,bash]
----
pyronaut test Foo.java
pyronaut test Foo.py
----

Test sources can also be supplied explicitly after `--`, which is useful for
custom test layouts:

[source,bash]
----
pyronaut test Foo.java -- FooTest.java
pyronaut test Foo.py -- FooTest.py
pyronaut test -t Foo.java -- *Test.java
----

An explicit `--` without test sources remains invalid.

Direct tests are compiled and executed in-memory through the JUnit Platform. Python direct tests use the JUnit engine and can use module-level `MicronautTest()`; pytest is not invoked because it requires test files on disk. Direct Java runs disable Python runtime infrastructure automatically; Python remains enabled by default for Python tests.

Use `--continuous` or `-t` to rerun direct tests when application or test sources change. The console prints execution progress and a final test summary.

Direct tests write JUnit XML and HTML reports to
`__pyronaut__/reports/tests` and print a terminal link to the HTML report.
Container startup failures that prevent tests from starting are included in the
report. Pass a directory after `--report` to choose another location:

[source,bash]
----
pyronaut test --report Foo.java -- FooTest.java
pyronaut test --report build/test-reports Foo.java -- FooTest.java
----

== Project Test Discovery

Python tests are discovered from the configured `python-test` source directory.
The default directory is `tests`.

[source,toml]
----
[tool.pyronaut.sources]
python-test = "tests"
----

Use `--tests` for selector-style filtering:

[source,bash]
----
pyronaut test --tests tests/test_controller.py::test_index
----

== Reports

Test reports are written under:

[source,text]
----
__pyronaut__/reports/tests/
----

Important files include:

- `index.html`
- `junit.xml`
- `.pyronaut-last-nodeid.txt`
- `events.ndjson`

With `engine = "both"`, the JUnit XML and HTML reports contain results from both engines. The node-id and event files remain pytest-specific.

== Context Tests

Use `MicronautTest` with the pytest fixture integration when a pytest needs a Micronaut `ApplicationContext`, injected beans, an `EmbeddedServer`, or configuration properties.
Use `pyronaut.requests` or the `requests` shim for HTTP tests against the embedded server.
