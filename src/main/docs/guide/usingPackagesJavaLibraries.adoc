= Using Python Packages and Java Libraries

Pyronaut applications can use both Python packages and Java libraries.
Install Python packages into a GraalPy virtual environment and declare Java libraries as Maven coordinates in `pyproject.toml`.

== Create a GraalPy virtual environment

Install https://github.com/pyenv/pyenv#installation[pyenv], then install and select the GraalPy version currently used by Pyronaut:

[source,bash]
----
pyenv install --skip-existing graalpy3.13-25.3.4.1
pyenv shell graalpy3.13-25.3.4.1
python --version
----

Change to your project directory:

[source,bash]
----
cd <project-dir>
----

Create and activate a GraalPy virtual environment:

[source,bash]
----
graalpy -m venv .venv
source .venv/bin/activate
python -m pip install pytest
python -m pytest --version
----

Use the `pip` installed by the GraalPy virtual environment.
It can apply GraalPy-specific package patches and select compatible distributions.

When a project contains `.venv`, Pyronaut automatically uses its Python executable and installed packages when launching the application and tests.
Create the virtual environment with GraalPy; Pyronaut cannot use packages from a CPython-created virtual environment in its embedded GraalPy runtime.

Pyronaut does not install Python packages when you run `pyronaut install`.
You can also record Python dependencies in the standard `[project].dependencies` table in `pyproject.toml`; see <<dependencies,Installing Python and Java Dependencies>>.

== Python package compatibility

WARNING: Package compatibility depends on the GraalPy version, native extensions, threading, and deployment mode. Test the exact package versions and deployment mode used by your application.

Support for packages containing native extensions remains experimental.
Native wheels that target CPython are not binary-compatible with GraalPy. Use a GraalPy-specific wheel for native extensions or build the extensions with GraalPy.
See the https://www.graalvm.org/python/compatibility/[GraalPy package compatibility checker] and https://www.graalvm.org/reference-manual/graalpy/[GraalPy reference documentation] for current compatibility and native-extension guidance.

Pydantic 2 depends on `pydantic-core`, which is partially written in Rust and exposed to Python as native code.
Because native-extension support remains experimental, test the exact Pydantic, GraalPy, and Pyronaut versions under the threading and deployment model your application uses. A passing compatibility-checker result covers only its tested configuration.

Many common Python library use cases have high-performance JVM alternatives that integrate directly with Micronaut:

== Optimise hot paths in Java

For CPU-bound work such as a tight parsing routine or numeric kernel, a Java implementation can run faster than Python. Add the Java class to the project's Java source directory (`src-java` by default; see <<projectStructure,Pyronaut Toolchain and Project Layout>>) and make it a bean:

[source,java]
----
package bookstore;

import jakarta.inject.Singleton;

@Singleton
public class PriceCalculator {
    public double total(double[] prices, double taxRate) {
        double sum = 0;
        for (double price : prices) {
            sum += price;
        }
        return sum * (1 + taxRate);
    }
}
----

`pyronaut process` compiles Java and Python sources together, so Python code can inject the bean through its type hint:

[source,python]
----
from bookstore import PriceCalculator
from micronaut.http.annotation import Controller, Get


@Controller("/orders")
class OrderController:
    def __init__(self, calculator: PriceCalculator):
        self.calculator = calculator

    @Get("/{order_id}/total")
    def total(self, order_id: int) -> float:
        prices = load_prices(order_id)
        return self.calculator.total(prices, 0.2)
----

Python lists convert to Java arrays and collections automatically, and the Java class participates in the same dependency injection, configuration, and tests as the rest of the application. Java code can also inject Python beans and call `async def` methods as `CompletionStage` values (see <<reactiveInterop,Awaiting Reactive and Java Async Types>>). Java tests belong under `test-java` and run in the same `pyronaut test` invocation.

== Use a Java library from Python

Declare Java dependencies by scope under `[tool.pyronaut.dependencies]`.
For example, add Apache Commons Lang to the runtime classpath:

[source,toml]
----
[tool.pyronaut]
repositories = ["mavenCentral"]

[tool.pyronaut.dependencies]
runtime = [
  "org.apache.commons:commons-lang3:3.20.0"
]
----

Resolve the dependency and refresh the generated Pyronaut project state:

[source,bash]
----
pyronaut install
----

The library is now available through a normal Python import. Pyronaut resolves the imported Java type from the configured classpath:

[source,python]
----
from org.apache.commons.lang3 import StringUtils

message = StringUtils.capitalize("hello from java")

print(message)
----

Use `group:artifact:version` coordinates for libraries such as Apache Commons Lang that are not managed by the configured Micronaut BOMs.
Micronaut dependencies managed by the Micronaut platform, Micronaut core, or Pyronaut BOMs can use versionless `group:artifact` coordinates.

For dependency scopes and install options, see <<dependencies,Installing Python and Java Dependencies>>.
See also <<pyproject,Configuring pyproject.toml>>, <<mavenRepositories,Configuring Maven repositories>>, and <<directSourceDeclarations,Declaring direct source dependencies>>.
