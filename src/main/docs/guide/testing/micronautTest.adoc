= Using MicronautTest

`MicronautTest` is the Python-side configuration object used by Pyronaut's pytest fixture support.
The fixture starts a Micronaut application context for pytest and exposes it through a Python wrapper.

[source,python]
----
import pytest

from pyronaut.test import MicronautTest, micronaut_test_fixture


@pytest.fixture
def my_context(request):
    fixture = micronaut_test_fixture(
        request,
        MicronautTest(
            environments=["test"],
            properties={"custom.property": "test_value"},
        ),
    )
    yield fixture
    fixture.stop()
----

`MicronautTest()` mirrors the options of the `@MicronautTest` annotation. The `environments`, `packages`, `start_application`, `properties` and `sql` options are fully supported by the pytest integration.

WARNING: The pytest fixture integration does not currently drive Micronaut Test's per-test transaction and context-rebuild lifecycle. The integration accepts `transactional`, `rollback` and `rebuild_context` for compatibility, but ignores them. It also does not run `Sql` scripts declared with `Sql.Phase.AFTER_ALL`. Use explicit clean-up in a fixture, or write the test as a JUnit 5 Python module (see <<testing,Testing>>), when transactional rollback is required.

== Common options

[source,python]
----
MicronautTest(
    environments=["test"],
    packages=[],
    transactional=False,
    rollback=True,
    rebuild_context=False,
    start_application=True,
    resolve_parameters=True,
    properties={}
)
----

`environments` defaults to `["test"]`.
The fixture passes additional properties into the Micronaut context during bootstrap.

== Bean lookup

The fixture returns an application context wrapper.
You can look up beans by class name, resolved type, or Python class when Pyronaut can resolve the Python type to its generated bean name.

[source,python]
----
import java


def test_environment(my_context):
    env = my_context["io.micronaut.context.env.Environment"]
    assert "test" in env.getActiveNames()


def test_environment_by_java_type(my_context):
    Environment = java.type("io.micronaut.context.env.Environment")
    env = my_context[Environment]
    assert env is not None
----

You can also delegate directly to the underlying Micronaut context:

[source,python]
----
def test_context_running(my_context):
    assert my_context.isRunning()
----

== Embedded server

When `start_application=True`, an `EmbeddedServer` is available from the context:

[source,python]
----
def test_server_port(my_context):
    server = my_context["io.micronaut.runtime.server.EmbeddedServer"]
    assert server.getPort() > 0
----

For HTTP tests, bind `requests` to the context so relative URLs target the embedded server:

[source,python]
----
import requests


@pytest.fixture
def client(my_context):
    return requests.with_context(my_context)


def test_health(client):
    response = client.get("/health")
    assert response.status_code == 200
----

== SQL scripts

Use `Sql` with `MicronautTest` to execute SQL scripts during the pytest lifecycle.
The fixture resolves the scripts with `ResourceLoader`, so classpath resources such as `classpath:sql/seed-data.sql` work the same way they do with Micronaut Test.

[source,python]
----
import pytest

from pyronaut.test import MicronautTest, Sql, micronaut_test_fixture


@pytest.fixture
def my_context(request):
    fixture = micronaut_test_fixture(
        request,
        MicronautTest(
            start_application=False,
            sql=Sql(
                scripts="classpath:sql/seed-data.sql",
                phase=Sql.Phase.BEFORE_EACH,
            ),
        ),
    )
    yield fixture
    fixture.stop()
----

Pass a list when you need multiple scripts or phases:

[source,python]
----
MicronautTest(
    sql=[
        Sql("classpath:sql/init-db.sql", phase=Sql.Phase.BEFORE_EACH),
        Sql("classpath:sql/seed-data.sql", phase=Sql.Phase.BEFORE_EACH),
    ],
)
----

`Sql` defaults to the `default` datasource and `javax.sql.DataSource`.
Use `data_source_name` or `resource_type` when the test needs another SQL resource.
The pytest integration executes `Sql.Phase.BEFORE_ALL`, `BEFORE_EACH` and `AFTER_EACH`; see the warning above regarding `AFTER_ALL`.
