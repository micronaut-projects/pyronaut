= Configuring pyproject.toml

`pyproject.toml` is the source of truth for Pyronaut's build-time and runtime project model.
It includes standard Python project metadata plus the `[tool.pyronaut]` tables consumed by the CLI.

== Minimal Structure

[source,toml]
----
[project]
name = "hello-pyronaut"
version = "0.1.0"
dynamic = ["scripts"]

[build-system]
requires = ["setuptools", "wheel", "tomli"]
build-backend = "setuptools.build_meta"

[tool.pyronaut]
repositories = ["mavenCentral"]

[tool.pyronaut.dependencies]
runtime = []
build = []
test = []
----

== Managed Versions

Pyronaut can resolve versionless Micronaut coordinates from configured BOM versions:

[source,toml]
----
[tool.pyronaut.core]
version = "5.2.2"

[tool.pyronaut.platform]
version = "5.1.0"
----

If these tables are omitted, Pyronaut uses the managed versions bundled with the current Pyronaut distribution, which `pyronaut --version` prints. Python support requires Micronaut Core 5.2 or later.

== Source Layout

Use `[tool.pyronaut.sources]` to move source and resource directories away from the defaults:

[source,toml]
----
[tool.pyronaut.sources]
python = "app"
python-test = "test/python"
java = "src/main/java"
java-test = "src/test/java"
resources = "app-config"
test-resources = "tests-config"
additional-resources = ["views", "assets"]
additional-test-resources = ["tests-fixtures"]
----

== Packaging, Processor, and Test Modes

Choose what `pyronaut build` produces when no packaging-shaping command-line
option is present:

[source,toml]
----
[tool.pyronaut.packaging]
format = "wheel-jvm"

[tool.pyronaut.processor]
mode = "jvm" # jvm|native
incremental = false
python-incremental-mode = "conservative" # conservative|optimistic
daemon = false

[tool.pyronaut.test]
mode = "jvm" # jvm|native
engine = "both" # junit|pytest|both
verbose = false # stream application and test framework output to the console
----

`format` accepts exactly `fat-jar`, `wheel-jvm`, `wheel-native`,
`wheel-crema`, `docker-jvm`, `docker-native`, or `docker-crema`. It defaults to
`wheel-jvm`. Command-line flags such as `--jar`, `--jvm`, `--native`, and
`--docker` override the configured format for that invocation.

The former `tool.pyronaut.build.mode` setting is no longer accepted. Migrate
`mode = "jvm"` to `format = "wheel-jvm"`, and `mode = "native"` to either
`format = "wheel-native"` for a closed-world build or `format = "wheel-crema"`
for a reusable native runtime.

The test engine defaults to `both`. Use `junit` for JUnit Jupiter tests, `pytest` for pytest tests, or `both` to execute both types.

`verbose` defaults to `false`: console output written while a test runs is
captured into the test reports rather than shown. Set it to `true`, or pass
`--verbose` to `pyronaut test`, to stream it to the terminal instead.

Native image settings and Docker image settings also live under `[tool.pyronaut.build]`.
For a Crema format, set `native-base = "default"` to use the configured
language-specific production runtime for the target platform, or set a
filesystem path or HTTP(S) URL to reuse a custom base created by
`pyronaut build --native-base`. Docker builds select Linux; host builds select
the current operating system.
A closed-world
`wheel-native` or `docker-native` format rejects a configured reusable base.
See the CLI reference for the full build option surface.
See <<incrementalProcessing,Incremental Processing>> before enabling incremental processing, the compiler daemon, or the optimistic Python dependency policy.

== Control Panel

The development/TUI Control Panel is opt-in and is disabled by default. Enable it for `pyronaut dev` and `pyronaut --tui` with:

[source,toml]
----
[tool.pyronaut.control-panel]
enabled = true
path = "/control-panel"
production-enabled = false
----

The command-line option `--control-panel` enables it for that invocation and overrides this setting. `pyronaut dev --control-panel` also works for direct source execution.
When development Control Panel support is enabled, Pyronaut also adds Micronaut Management and the Control Panel management integration to the development runtime so health and diagnostic panels are available.
The implicitly enabled development Control Panel dependencies are written only to the `development-runtime` dependency manifest, so they are not packaged by `pyronaut build`.
Applications can declare their own development-only runtime dependencies with `development-runtime = [...]` under `[tool.pyronaut.dependencies]`.

Set `production-enabled = true` only when the application has Micronaut Security on the runtime classpath and the Control Panel should be included in production runtime artifacts.
Production Control Panel inclusion keeps the Micronaut Control Panel security defaults; the anonymous access used by `pyronaut --tui` is not applied to production builds.

== Toolchain

Commands that delegate to Java use a GraalVM JDK.
You can let Pyronaut discover a compatible installed JDK, or pin a toolchain:

[source,toml]
----
[tool.pyronaut.toolchain]
type = "jvm" # jvm|native
distribution = "ee"
java-version = 25
version = "25i3"
----

Development builds can use `distribution = "dev"` with a `release-tag` or explicit `download-url`.
Use `type = "native"` to route supported CLI lifecycle commands through the native `pyronaut-dev` uber CLI.
It selects how CLI tooling executes; it does not select the output of
`pyronaut build`. Use `[tool.pyronaut.packaging]` for the build default.
