= Declaring Direct Source Dependencies

Direct Java and Python source execution can declare Maven dependencies, repositories, and Micronaut properties without a `pyproject.toml`.
These declarations apply only when running direct sources without `--setup`.

== Java

Place repeatable annotations in `package-info.java`, or directly on the class when
running a single Java source file:

[source,java]
----
@Dependency(group = "org.apache.commons", module = "commons-lang3", version = "3.20.0")
@AppConfig(name = "datasources.default.dialect", value = "Oracle")
package example;

import pyronaut.build.AppConfig;
import pyronaut.build.Dependency;
----

For example, `App.java` can be self-contained:

[source,java]
----
package example;

import org.apache.commons.lang3.StringUtils;

@Dependency(group = "org.apache.commons", module = "commons-lang3", version = "3.20.0")
@AppConfig(name = "example.value", value = "configured")
class App {
    void useDependency() {
        StringUtils.defaultIfEmpty("", "default");
    }
}
----

Use `scope = Dependency.Scope.BUILD` for annotation processors and `scope = AppConfig.Scope.BUILD` for annotation processor options.

Direct declarations also support test dependencies, BOMs, and transitive exclusions:

[source,java]
----
@Dependency(group = "io.netty", module = "netty-bom", version = "4.2.17.Final", scope = Dependency.Scope.BOM)
@Dependency(group = "io.netty", module = "netty-handler", exclusions = {"commons:commons-lang"})
@Dependency(group = "org.junit.jupiter", module = "junit-jupiter-engine", scope = Dependency.Scope.TEST)
----

`BOM` declarations provide dependency management without being placed on the classpath. `TEST` declarations are available to `pyronaut test` and are omitted from normal run and dev classpaths. Python declarations use the corresponding `Dependency.Scope.BOM` and `Dependency.Scope.TEST` values and may pass `exclusions=["group:artifact"]`.

== Conditional Test Resources

Direct `pyronaut dev` and `pyronaut test` commands inspect runtime dependencies together with inline runtime `@AppConfig` declarations.
When an inferred Micronaut Test Resources provider can supply a missing property in a configured namespace, Pyronaut starts or attaches to a project-local Test Resources server for that launch.
Dependencies alone, build-scoped configuration, fully supplied connection properties, `--property`, `-D`, and `--config` do not activate automatic orchestration.
Use `--disable-test-resources` to turn it off explicitly.
Direct `pyronaut run` remains production-only and never activates Test Resources.

Run it in development mode, then insert and query repository-backed data:

[source,bash]
----

----

Both requests return `1`. The first launch starts the inferred MySQL container; stopping the development process also stops the owned Test Resources server. An already-running project-local server is attached to without transferring ownership.

== Python

[source,python]
----
from pyronaut.build import AppConfig, Dependency

Dependency(group="org.apache.commons", module="commons-lang3", version="3.20.0")
AppConfig(name="datasources.default.dialect", value="Oracle")
----

== Repositories and cache

Declare a repository with `MavenRepository("https://repository.example.com/maven/")` in Java or Python.
Maven Central is used when no repository is declared; once a repository is declared, only declared repositories are used.

Pyronaut records resolved direct-source dependencies and the declaration fingerprint in `__pyronaut__` under the project directory (the current working directory unless `--project-dir` is given). The cached launch metadata includes command eligibility, sorted inline runtime configuration, and the positive or negative Test Resources decision. A subsequent launch with unchanged inputs reuses that cache.
