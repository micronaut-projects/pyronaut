= Configuring Maven Repositories

Pyronaut resolves Java dependencies through Apache Maven Resolver. This includes
project installation, direct-source execution, and the SDK dependencies resolved
by `pyronaut setup`.

Direct-source applications can declare `MavenRepository`; see
<<directSourceDeclarations,Declaring Direct Source Dependencies>>.

== Project repositories

Configure repositories for a project in `[tool.pyronaut]`:

[source,toml]
----
[tool.pyronaut]
repositories = [
  "mavenCentral",
  "mavenLocal",
  "https://repo.gradle.org/gradle/libs-releases",
  "../build/fixture-repo"
]
----

Supported entries are:

* `mavenCentral`: Maven Central
* `mavenLocal`: the effective Maven local repository
* `https://...` or `file://...`: a remote or local Maven repository URL
* relative or absolute file paths: local Maven repository directories

Relative project paths are resolved against the project directory. An explicit
non-empty project list replaces the global default list, but global
`prepend-repositories` entries are still searched first.

`mavenLocal` is a source repository entry. It is separate from the install
destination selected by `pyronaut install --local-repository`. By default, that
destination is also Maven local, so many local development flows do not need to
list `mavenLocal` explicitly. Use it when a dependency was published locally
and no other configured repository provides it.

If a project omits `repositories` (or leaves it empty), Pyronaut uses the
non-empty `[maven].repositories` list from the user settings file. If that list
is also omitted, Pyronaut uses Maven Central. Direct-source declarations use the
same fallback when they do not declare a `MavenRepository`.

Use `prepend-repositories` when a repository must be available even when a
project declares its own repositories. Entries are searched in the listed order
before the project repositories or the global default list. This is useful for
a source-built repository in CI while retaining a fixture repository declared
by the project:

[source,toml]
----
[maven]
prepend-repositories = ["build/source-repository"]
repositories = ["mavenCentral"]
----

Relative prepend paths are resolved against the directory containing
`settings.toml`; relative project paths continue to be resolved against the
project directory. Pyronaut keeps the project repository identities stable so
cached `_remote.repositories` provenance remains usable in offline mode.

== Global repositories

The global settings file is `settings.toml` in Pyronaut's configuration
directory (normally `~/.pyronaut`; with the XDG layout it is
`$XDG_CONFIG_HOME/pyronaut`). Configure shared defaults with `[maven]`:

[source,toml]
----
[maven]
repositories = [
  "mavenCentral",
  "https://repo.example.com/snapshots/"
]
----

`pyronaut setup` uses this list for SDK resolution. Relative paths in this list
and in `prepend-repositories` are resolved against the directory containing
`settings.toml`, not the project directory.

When project, direct-source, or SDK resolution falls back to the automatic
defaults, snapshot resolution also consults the local Maven repository and the
Sonatype Central snapshots repository. A non-empty global list used as that
fallback replaces the defaults and suppresses the automatic Sonatype addition;
include the snapshots URL yourself when it is needed. An explicit project
repository list retains the existing automatic snapshot behavior. Set
`PYRONAUT_SONATYPE_SNAPSHOTS=false` (or
`-Dpyronaut.sonatype.snapshots.enabled=false`) to disable automatic snapshot
lookup.

== Mirrors

Add Maven mirror rules as repeatable `[[maven.mirrors]]` tables. The `mirror-of`
value uses Maven Resolver's matching syntax: comma-separated repository IDs,
`external:*` for external repositories, `*` for every repository, and `!id` to
exclude an ID.

For example, this configuration keeps a local pipeline fixture available while
mirroring external repositories:

[source,toml]
----
[maven]
repositories = [
  "file:///opt/build/maven-repository",
  "mavenCentral"
]

[[maven.mirrors]]
id = "company-mirror"
url = "https://maven.example.org/mirror/"
mirror-of = "external:*"
----

`external:*` does not match local `file://` repositories. To mirror only Maven
Central and leave an external pipeline URL alone, use the repository IDs
explicitly:

[source,toml]
----
[[maven.mirrors]]
id = "central-mirror"
url = "https://maven.example.org/mirror/"
mirror-of = "mavenCentral,central"
----

Mirrors apply both to repositories configured as resolution roots and to
repositories discovered from POM files. A mirror changes the repository used
for resolution; it does not change the repository declarations in the project
or POM.

An explicit `--lock-repository` takes precedence over global repository defaults
and mirror rules. See <<dependencyLocking,Locking Maven Dependencies>>.

== Repository credentials

Configure HTTP Basic credentials in user settings with `[[maven.credentials]]`.
Each entry applies to one repository URL, including its path:

[source,toml]
----
[[maven.credentials]]
url = "https://maven.example.org/repository/private/"
username-env = "PYRONAUT_MAVEN_USERNAME"
password-env = "PYRONAUT_MAVEN_PASSWORD"
----

Provide the named environment variables through your shell or CI secret settings.
For literal values, use `username` and `password` instead of the corresponding
`-env` fields. Each field must select exactly one source. Tokens can be supplied
as the password when the repository supports token-based HTTP Basic authentication.

Credentials are selected using the effective repository URL after mirror selection.
For an authenticated mirror, configure its URL in the credentials entry. Matching
ignores trailing slashes. Separate repository roots on the same host need separate
entries. This applies to project, SDK, native-classpath,
and direct-source resolution, including repositories discovered from POM files.

Environment variables are read only for matching repositories during online
resolution. Missing variables produce a configuration error; offline resolution
of cached artifacts does not require them. Secret environment values are not
added to cache fingerprints or SDK metadata, so rotating a secret does not
invalidate already cached artifacts.

== Maven resolution policy

The global Maven table can also control retries and versions for application
resolution:

[source,toml]
----
[maven]
retry-count = 2

[maven.version-overrides]
"org.example:example-library" = "1.2.3"
----

`retry-count` is the maximum number of HTTP retries after the initial attempt;
zero disables retries. Omitting it retains Maven Resolver's default retry policy.
Version overrides use exact
`group:artifact` module keys and apply to managed, explicitly declared, and
transitive application dependencies. SDK and native compiler descriptors carry
exact versions by design; rebuild those descriptors from the Gradle version
catalogs when changing their versions. For Graal build tests, supply overrides
for every GraalPy, Truffle, and SDK module that must use the pipeline version.

For a CI bundle, a trusted lock can verify selected Maven groups independently
of the project's `pyronaut.lock`:

[source,toml]
----
[maven]
prepend-repositories = ["/ci/build/source-repository"]
repositories = ["mavenCentral"]
retry-count = 2

[[maven.mirrors]]
id = "ci-central"
url = "https://maven.example.org/central/"
mirror-of = "mavenCentral,central"

[maven.version-overrides]
"org.graalvm.python:python-language" = "25.5.5"

[maven.verification]
lock-file = "/trusted/bundle/pyronaut.lock"
groups = ["org.graalvm.*"]
----

Verification requires every resolved JAR and POM in the selected groups to be
listed with its SHA-256 in the trusted lock. Sources and Javadoc are optional editor artifacts and are
not required. When verification is active, warm dependency-graph shortcuts are
disabled: cached Maven files are checked on every invocation, while matching
files are reused without downloading them. The bundle pipeline must supply a
fresh trusted lock generated from its source-built artifacts, using the
<<dependencyLocking,existing lock file format>>. Include all selected groups
used by the gate, including SDK and native compiler artifacts. Never promote a
lock recorded from the test cache to the bundle's checksum authority. Use an isolated local repository
for bundles that reuse coordinates. The raw trusted lock is part of the cache
fingerprint. Verification establishes checksum identity; it does not preserve
the artifact's original transport origin. Group selectors are exact group IDs
or prefixes ending in `.*`. A normalized `-SNAPSHOT` cache entry requires a
single matching timestamp in the trusted lock; ambiguous entries fail verification.

When verification is active, installation records the resolved coordinates and local file paths in
`__pyronaut__/verified-maven-artifacts.json`. The versioned JSON report includes
the Maven settings fingerprint and the POMs used to build the dependency graph.
Cached commands, including `--no-install`, use these identities to recheck the
selected files against the trusted lock. Run `pyronaut install` if the report is
missing or the Maven settings changed. The report describes the local resolution;
the bundle's trusted lock remains the checksum authority.

== Settings, caches, and isolation

The settings file and its directory are part of the Java/Python install and SDK
resolution cache fingerprints. Editing any section of `settings.toml` invalidates
those cache entries. Run `pyronaut install` again for a project; if setup is reported stale, run
`pyronaut setup` (use `--refresh` to force re-resolution).

When a repository rebuilds an artifact under the same coordinates, use
`--refresh`. For separate bundles that reuse coordinates, use an isolated local
repository per bundle, for example:

[source,bash]
----
pyronaut install --refresh --local-repository .pyronaut-m2/bundle-a
----

To isolate the configuration and SDK state for a complete command or test gate,
set `PYRONAUT_HOME` to a separate directory. Child Java, launcher, and Python
processes inherit the resulting state locations:

[source,bash]
----
export PYRONAUT_HOME="$PWD/.gate-pyronaut"
mkdir -p "$PYRONAUT_HOME"
# Save the repository configuration above in "$PYRONAUT_HOME/settings.toml".
pyronaut setup
----

These settings configure Pyronaut's embedded Maven Resolver. Gradle repositories
remain independently configured in the Gradle build. Pyronaut does not import
mirrors or server credentials from Maven `settings.xml`; it only uses an
active Maven proxy from `~/.m2/settings.xml` as the proxy fallback when no
environment or Pyronaut proxy is configured. See <<proxyConfig,Proxy
Configuration>>.
