= Configuring Maven Repositories

Pyronaut resolves Java dependencies through Apache Maven Resolver.

Direct-source applications can instead use `MavenRepository`; see <<directSourceDeclarations,Declaring Direct Source Dependencies>>.
Configure remote and local repositories in `[tool.pyronaut]`:

[source,toml]
----
[tool.pyronaut]
repositories = [
  "mavenCentral",
  "mavenLocal",
  "https://repo.gradle.org/gradle/libs-releases",
  "../build/fixture-repo"
]
----

Supported entries:

- `mavenCentral`: Maven Central
- `mavenLocal`: the effective Maven local repository
- `https://...`: a remote Maven repository URL
- relative or absolute file paths: local Maven repository directories

If `repositories` is omitted or empty, Pyronaut uses Maven Central. Pyronaut resolves relative file paths against the project directory.

When the configured Micronaut Core version or the installed Pyronaut SDK is a snapshot, Pyronaut additionally consults the Sonatype Central snapshots repository and the local Maven repository so that snapshot artifacts resolve. Set `PYRONAUT_SONATYPE_SNAPSHOTS=false` (or `-Dpyronaut.sonatype.snapshots.enabled=false`) to disable the snapshot repository.

The repositories above are project repositories used by `pyronaut install`.
The global `pyronaut setup` command has a separate repository list in `~/.pyronaut/settings.toml`:

[source,toml]
----
[maven]
repositories = ["mavenCentral"]
----

If this global list is omitted, setup uses Maven Central and automatically adds the Sonatype Central snapshots repository when the installed Pyronaut SDK version is a snapshot.
An explicit global list replaces those defaults.

`mavenLocal` is a source repository entry.
It is separate from the install destination selected by `pyronaut install --local-repository`.
By default, the install destination is also Maven local, so many local development flows do not need to list `mavenLocal` explicitly.

Use `mavenLocal` when you published the dependency locally and no other configured repository provides it.
