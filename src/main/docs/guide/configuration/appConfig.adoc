= Application Configuration with application.toml

Micronaut application configuration lives in the configured resources directory.

Direct source applications can declare individual runtime properties with `AppConfig`; see <<directSourceDeclarations,Declaring Direct Source Dependencies>>.
By default, that directory is `config`, so the main configuration file is:

[source,text]
----
config/application.toml
----

Pyronaut adds Micronaut TOML support to the runtime classpath by default when dependencies are managed from the Micronaut platform.

== Basic Configuration

[source,toml]
----
[micronaut.application]
name = "hello-pyronaut"

[micronaut.server]
port = 8080

[endpoints.all]
enabled = true
sensitive = false
----

== Executor Defaults

Pyronaut supplies the following low-priority defaults for Micronaut executors:
This follows the https://github.com/micronaut-projects/micronaut-core/commit/1edbbb9f2d1627dedfd5a95d0a7eb7fd543f4029[Micronaut Core Python threading guidance].

[cols="2,1,4", options="header"]
|===
|Property |Default |Why Pyronaut changes the default

|`micronaut.executors.io.type`
|`cached`
|Uses a cached platform-thread executor for I/O work that may execute Python code.

|`micronaut.executors.io.virtual`
|`false`
|GraalPy does not support executing Python code on virtual threads, so the I/O executor must use platform threads.

|`micronaut.executors.blocking.type`
|`cached`
|Uses a cached platform-thread executor for blocking work that may execute Python code.

|`micronaut.executors.blocking.virtual`
|`false`
|GraalPy does not support executing Python code on virtual threads, so the blocking executor must use platform threads.
|===

These defaults are applied only when the application does not provide a value. Normal application configuration, including `application.toml` or `application.properties`, can override them, and partial configuration leaves the unspecified defaults in place.

Environment-specific files use the Micronaut naming convention:

[source,text]
----
config/application-test.toml
config/application-dev.toml
----

The configured `resources` directory and any `additional-resources` directories are included for `dev`, `run`, `test`, and build flows.
The configured `test-resources` directory and any `additional-test-resources` directories are included for `dev` and `test` flows.

== Schema Support

When `application.toml` exists, `pyronaut install` builds a JSON schema from Micronaut configuration metadata present on the resolved runtime classpath.
It writes the schema to:

[source,text]
----
__pyronaut__/schemas/micronaut-application.schema.json
----

If `application.toml` does not already contain a user-managed schema directive, Pyronaut prepends one so TOML-aware editors can validate Micronaut configuration keys.

== Validation

Use:

[source,bash]
----
pyronaut validate-config --scenario dev
pyronaut validate-config --scenario test
pyronaut validate-config --scenario production
----

`pyronaut dev`, `pyronaut run`, `pyronaut test`, and native build flows run scenario-specific validation by default.
